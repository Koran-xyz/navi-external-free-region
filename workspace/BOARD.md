# GEMINI 改善依頼｜簡易エージェント 第1回修正
DATE: 2026-11-26
FROM: GOTEN
TO: GEMINI
PRIORITY: HIGH
STATUS: READY_FOR_GEMINI

## 目的
Geminiが作成した「簡単なエージェント」を、販売・実運用に耐える軽量版へ改善する。

重要:
**大きく複雑化しない。軽量さを維持したまま、誤動作・誤完了・危険な外部操作を防ぐ。**

## 修正してほしい点

### 1. 「メタルールを全部抜く」ではなく、最低限の製品安全ルールを残す
研究コアのNLEE / GCGW / Navi内部ルールは商品へ混入させない。
ただし、以下は製品側の軽量安全ルールとして必須。

- 未確認事項を事実として補完しない
- 実行していない操作を「完了」と言わない
- 外部送信・削除・公開・購入・重要変更は既定DENY
- 必要時は人間確認へ回す
- 秘密情報を出力・保存しない

### 2. 不明値の扱いを明確化
不明・曖昧な値は推測して埋めない。

推奨:
- `要確認`
- `UNKNOWN`
- `UNVERIFIED`

のどれかを用途別に固定する。

「AI自身の信頼度が低いから要確認」ではなく、
**入力中に根拠が明示されているか、必須項目が揃っているか、形式検証を通ったか**
で判定する。

### 3. 出力形式を固定
自由文だけでなく、後工程へ渡せる構造化出力を持たせる。

最低限:
- status
- confirmed
- needs_confirmation
- output
- next_action

必要に応じてJSON化する。

### 4. 実務モードと相談モードを分ける
通常は余計な会話をせず、実務処理を優先。
設定変更、エラー相談、項目追加などの時だけ相談モードを出す。

例:
- EXECUTION_MODE
- SUPPORT_MODE

### 5. 誤完了防止
以下を区別する。

- DRAFT
- PENDING_CONFIRMATION
- COMPLETED
- BLOCKED

人間確認が必要な状態をCOMPLETEDにしない。

### 6. 外部操作は「生成」と「実行」を分離
例:
返信文を作る → OK
実際にメール送信する → 人間承認が必要

ファイル変更案を作る → OK
実際に削除・上書きする → 原則禁止または承認必須

### 7. ローカル処理は非破壊を基本
Excel等を扱う場合:
- 元ファイル上書き禁止
- 別名保存
- 保存後の再読込・検証
- 書式保持を「必ず完全維持」と断定しない
- 重要な書式・数式・結合セルは保存後チェック

### 8. 研究コアと販売製品を混ぜない
商品エージェントには、
- NLEE内部設計
- GCGW研究コア
- Navi内部統制
- 研究用メタルール全文

を含めない。

必要なのは、その商品が安全に働くための最小ルールだけ。

### 9. ログは軽量にする
最低限、以下だけ残せる構造にする。

- input_received
- action_taken
- result
- unresolved
- timestamp

ただしNotionへ直接書き込むことを標準にはしない。

### 10. 最終確認
Gemini側で修正版を作成後、次を返すこと。

- 変更した点
- 残した安全ルール
- 削った不要部分
- まだ不安な点
- テスト方法
- 修正版の保存場所 / ファイル名

## 変更禁止
- 研究コアを販売製品へ入れない
- 外部操作を自動許可しない
- 人間承認なしで公開・送信しない
- 未確認情報を確定扱いしない
- 「軽量エージェント」を大型化しすぎない

## 完了条件
Geminiが修正版を作り、
「軽量」「安全」「実務優先」「誤完了防止」
の4点を満たしたことを説明する。
